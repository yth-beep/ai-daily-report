agent from scratch（B站合集·10集）

bilibili · NotTechSavvy · AI 大模型

视频链接：https://space.bilibili.com/2537381/channel/collectiondetail?sid=8031879

推荐等级：强烈推荐

核心问题：不套 LangChain 一类框架，从零手写一个「Claude Code」式编码智能体，需要哪几层抽象；Skill 与 SubAgent 又该怎么接进这套骨架？

关键方法 / 结论：10 集按 CodeCrafters 的 build-your-own-Claude-Code 关卡推进，主线是四层抽象逐层加码。① 工具注册：手写 JSON Schema（name/description/parameters/properties/required），再用 pydantic BaseModel 结构化，工具名到真实函数的映射由此建立。② 工具调用：模型返回 tool_call 带 id，下一轮必须把同一个 id 回填，否则模型对不上语义；只用一轮循环不算 agent。③ agent loop：ReAct 式，response 追加进 messages，没有工具调用才退出，有则执行后继续喂回。④ 工具补全：write_file 之后是 bash——bash 基本等于交出整机控制权，作者的取舍是执行前先打印命令、只在沙盒里跑，权限与目录越界不在教学范围。⑤ Skill 层：skill 是一个文件夹加 SKILL.md，front matter 只先暴露 name/description 进上下文，被调用后才把正文加载进来，这就是渐进式披露；参数按占位符展开。⑥ 多 Skill 连续调用时用两个布尔量做状态机：连续的 skill 一起展开，一旦被非 skill 隔开，后面的都算前一个 skill 的参数。⑦ SubAgent：skill 带 fork 标记时子智能体只拿一条消息、没有 system prompt、不支持嵌套 skill，主 agent 同步等返回，作者明确不走并发。⑧ 收尾把 LSP 当普通工具接入（go-pls 为例，pyright 要额外配依赖路径，因为 uv 与 pip 装库位置不同）。作者刻意不用框架、当场踩 schema 与类型错误，踩坑过程本身就是内容。

为什么推荐：这条链路正好覆盖 AI 大模型应用侧最难自学的部分：工具协议怎么声明、上下文怎么管理、渐进式披露怎么省 token、子智能体怎么隔离。它属于 AI 大模型（Agent 工程），与嵌入式 Linux 无关，不要混着看。相比读框架源码，手写一遍更容易建立体系感，也更容易在面试里讲清 tool_call id、Skill front matter、fork 隔离这些细节。

适用场景：已经日常在用 Claude Code / Codex、想自己造一个最小可用 agent，或准备 Agent 工程方向面试的阶段。建议先 1–6 集把 loop 跑通（工具注册→调用→循环→write/bash），再进 7–10 集的 Skill、多 Skill 展开、SubAgent 与 LSP，否则容易只抄代码不懂边界。

【AI大模型本地推理 11-27】单卡跑大模型预填充大涨：单卡长文预填充为何大涨

bilibili · umRick · AI 大模型

视频链接：https://www.bilibili.com/video/BV1i71nznEXt

推荐等级：推荐

核心问题：单张 24GB 显卡配 64GB 内存跑 MoE 大模型做长文预填充，为什么换了推理内核就能快近一倍，瓶颈到底在显存容量还是在内核调度？

关键方法 / 结论：测试台是一张 24GB 显卡加 64GB 内存，专家权重放内存、靠总线交换，上下文开到 262K，KV 缓存走 INT8，采样保持常见设置。换新内核后：短提示词预填充从 1330 提到 2371，4 万 token 到 2877，8.4 万 token 仍有 2715/2675，说明长文段没有明显衰减；解码靠草稿模型投机，接受率约 84%，输出稳定在 50–60 token/s；专家缓存命中率 85%–89%，作者把两倍提升直接归因于内核更会调度内存里的专家权重、让命中率维持在这个区间，而不是加显存或换卡。字幕为语音转写，显卡型号与个别数字可能有偏差，结论方向可用、具体数值建议自测复核。

为什么推荐：本地推理最贵的误区是「显存不够就换卡」。这条把变量控制在同一台机器上，只换内核，给出预填充/解码/命中率三组对照，属于 AI 大模型侧的推理工程经验；对想在自己机器上跑长文问答、代码库分析的人是可直接复现的调参方向，不涉及板卡、驱动或端侧部署。

适用场景：已有本地推理环境、准备升级推理引擎或驱动，或正在纠结要不要加显存的阶段。做法是固定自己的上下文长度和提示词，先量旧内核与新内核的预填充、解码和专家缓存命中率，再决定是否买卡。

【AI大模型本地推理 11-27】十二G显卡五款模型实测：五款模型同场，速度能力显存全比

bilibili · umRick · AI 大模型

视频链接：https://www.bilibili.com/video/BV1LK1WzxEgt

推荐等级：推荐

核心问题：只有 12GB 显存时，该按榜单总分挑本地模型，还是按「装得下、跑得稳、任务类型对得上」来挑？

关键方法 / 结论：同一台机器（12GB 显卡 + 64GB 内存，32K 上下文，单请求并发，默认思考等级）让五款本地模型跑同一套 54 项任务：12 项智能体、18 项编码、24 项难题，速度与能力分开记。结果出现分歧——总分最高的一款并不是速度最快的；速度第一的是一款带草稿（投机解码）机制的小模型，接受率约 89%，32K 上下文只占约 9.4GB 显存，但它的编码任务只有 13 项，长板与短板都很极端。作者给出的选型顺序是三步：先问装不装得下（显存占用），再问跑得快不快，最后看草稿机制稳不稳；不要只看总分。字幕为语音转写，模型名称有明显失真，按「大参数量旗舰 / 带草稿机制的小模型」这类特征对号即可。

为什么推荐：把本地选型从「看排行榜」拉回到显存占用加任务结构匹配，这是 AI 大模型本地部署最通用的一条方法；对只有消费级显卡的学习者，能省掉「装不下」和「装得下但慢」两类弯路，也和同日的预填充、双卡两条形成一组对照实验。

适用场景：手上是 12–16GB 显卡、准备挑一个本地主力模型，或要给自己的任务集（编码、智能体、长文问答）做一次小型选型评测的阶段。照抄它的 54 项任务结构不现实，可压缩成 10 项自己的真实任务再跑。
