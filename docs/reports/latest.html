Linux命令精讲之dmesg/journalctl（系统日志）

bilibili · 全栈二把刀 · 嵌入式 Linux 基础（当前主线）

视频链接：https://www.bilibili.com/video/BV1Pq8B64ExD

推荐等级：强烈推荐

核心问题：板子起不来、驱动加载失败、服务自启不了时，先看哪份日志、用哪几个命令把范围缩到具体一行。

关键方法 / 结论：先把两层日志分开：dmesg 读的是内核环形缓冲区，开机时的 CPU 检测、内存初始化、PCI 扫描、磁盘识别、驱动 probe 都在这里，缓冲区满会覆盖旧消息；journalctl 读的是 systemd 统一日志库，按时间索引、可持久化。定位套路是先用 dmesg | grep 关键词 抓内核侧线索，再用 journalctl -u 服务名 看单个服务、-k 只看内核、-b 只看本次启动、--since/--until 卡时间窗、-f 实时跟、-x/-e 看详细上下文；要长期留存得开 Storage=persistent，空间不够用 --vacuum 清旧日志。

为什么推荐：嵌入式 Linux 上板的第一阶段就是“串口 + 日志”定位问题，这条把内核层与系统服务层两条线一次打通，是后面调驱动、调自启动服务共用的底座能力，比零散的单个命令视频更成体系。

适用场景：适合从“会敲命令”过渡到“能独立排障”的阶段；板子卡在启动、驱动没 probe 上、服务开机不自启时，按内核层到服务层的顺序查。
