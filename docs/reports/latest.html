01_端侧AI、边缘AI、嵌入式AI和TinyML到底有什么区别

bilibili · 端侧AI贺老师 · AI大模型 + 嵌入式

视频链接：https://www.bilibili.com/video/BV1kGH76CEnJ

推荐等级：强烈推荐

核心问题：同一块设备被不同文章分别叫成端侧 AI、边缘 AI、嵌入式 AI、TinyML，到底按什么标准判断它其实属于哪一类。

关键方法 / 结论：判断依据是三个维度：部署位置（模型真正执行计算的那颗芯片在哪）、硬件资源（可用存储、内存、算力与功耗预算）、应用边界（它负责哪一步、哪些功能要别的设备协作）。关键动作是追踪“真正跑模型计算的位置”，而不是看设备离人有多近——设备在手里、模型在云端，那仍算云端推理。视频用一条产线把四个概念串起来：传感器旁的 STM32 做异常初筛属于端侧 AI；因为它集成进监测产品、受产品硬件与运行条件约束，同时属于嵌入式 AI；若按小内存低功耗实现，就落进 TinyML 的讨论范围；网关汇总多台设备数据、在现场做分析，体现的是边缘 AI 的“靠近数据产生处”。后面才进入模型训练与单片机部署。

为什么推荐：这四个词在招聘 JD、芯片选型和课程大纲里被混用得很厉害，先立起这套判断框架，后面看任何端侧部署方案都能立刻分清“它说的边缘是指网络位置还是算力档位”，也才知道自己项目该按哪一类的资源约束去设计。对“AI大模型+嵌入式”方向来说，这是最省后续返工的一块地基，比直接抄一份部署教程更值。

适用场景：现在就能看，属于入门第一课。适合放在准备端侧项目选型（要不要上 NPU、模型压到多少参数、算法放设备还是放网关）之前；也适合在读开发板与芯片宣传页时用来做交叉验证。

03_TinyML不是用来替代所有传统算法的

bilibili · 端侧AI贺老师 · AI大模型 + 嵌入式

视频链接：https://www.bilibili.com/video/BV1RBpE6BE6X

推荐等级：强烈推荐

核心问题：单片机能跑模型之后，原来的阈值判断、状态机、PID 到底还要不要留，哪些任务该交给规则、哪些才值得上小模型。

关键方法 / 结论：按任务性质分工，而不是按“新旧”取舍。判断依据能写清楚的（温度超上限报警、限位开关触发停机）用比较加状态记录就够，其中“上限与恢复阈值之间留一段间隔”的迟滞设计，可以避免被测量在边界附近波动时反复切换；控制目标明确的（转速跟随设定值）交给 PID，没必要为了用 AI 把已经满足要求的成熟控制环整体换掉；只有“听声音判断有没有异常摩擦”这类复杂模式识别，才是小模型的候选任务。方法演进顺序是单阈值 → 多条件规则 → 人工特征（如频谱特定频段的能量或峰值）→ TinyML 模型，这是可选的复杂度阶梯，不要求每个项目都走到最后一格。模型输出还要再经一层逻辑映射才能变成系统事件，最后用项目评审清单比较实际效果、资源占用与维护成本，再决定引入模型有没有收益。

为什么推荐：这条纠正的是端侧 AI 最常见的误用——以为上了模型就该替掉所有规则。工程上规则的可解释、可测试、执行时间与资源可控是不可替代的优势，模型只该啃规则啃不动的部分。你之后做电机监测、传感器异常判断这类题目时，这套分工能直接避免做出“黑盒且不稳、出了问题说不清”的方案。

适用场景：在已经跑通一次单片机推理、开始设计真实项目的判断逻辑时看最有价值；也可作为方案评审或毕设开题时的对照清单，逐项问“这一段现有规则在哪些真实输入上会失败”。

单片机项目ADC乱飙你还限幅滤波？

bilibili · 单片机编程六哥 · AI大模型 + 嵌入式

视频链接：https://www.bilibili.com/video/BV1eBWe6mEug

推荐等级：推荐

核心问题：单片机 ADC 读数乱跳时，为什么上手就加限幅滤波是错的，正确的排查顺序是什么。

关键方法 / 结论：把动作排成“先查硬件、再谈算法”。第一步用示波器看 VDDA 供电与 VREF 基准的实际纹波，确认基准源和调理电路本身的噪声水平，而不是相信手册标称值；第二步做阻抗匹配，按信号源输出阻抗与 ADC 采样保持网络的匹配关系去定采样时间与采样周期，采样时间选短了读数必然飘；第三步才进软件——用定时器触发采样拿到等间隔的高速数据，做过采样与抽取把有效位数抬上去；最后按噪声特征选滤波器，工频干扰用陷波、偶发尖峰用中值、随机噪声才轮到卡尔曼，而不是一律“求平均+限幅”。归纳成三条硬要求就是：基准与供电必须实测、过采样与抽取要会、滤波器要按噪声类型分工。具体参数需按自己的板子实测决定，视频没有直接给数值。

为什么推荐：这是少数把“硬件先行”讲明白的实操内容，而 ADC 是端侧设备拿数据的入口——采样不可靠，后面模型再好也是在喂噪声。你主线虽然在 Linux 侧，但传感器数据从 ADC、I2C 进来这一段绕不开，这套排查顺序可以原样迁移到任何采集链路上，属于学会一次到处能用。

适用场景：做传感器采集、电压电流监测，或调试“读数抖动、偶发野值、滤波后仍有毛刺”时直接照这个顺序走；也适合当作硬件调试检查表存档，接在 I2C 外设调试之后。
