DeepSeek的省显存秘诀：MLA把KV缓存压小57倍｜图解大模型架构09

bilibili · 图解AI_Infra · AI 大模型

视频链接：https://www.bilibili.com/video/BV1busQ6sEv2

推荐等级：强烈推荐

核心问题：DeepSeek 参数量比 80 亿小模型大一个量级，为什么每 token 的 KV 缓存反而只有它的一半，MLA 到底把什么省掉了。

关键方法 / 结论：用“4×4 乘法表只要记住一行一列就能还原整张表”类比低秩：128 个头的 K/V 表面有几万个数，但彼此高度相关，真正独立的信息没那么多，于是每个 token 先压成一个 512 维潜在向量，缓存里只存这 512 个数，做注意力时再用矩阵展开成各头的 K/V。真正的巧劲在矩阵吸收——矩阵乘法可以先乘后乘换顺序，把展开矩阵并到 Q 一侧（V 侧并进输出矩阵），注意力直接在压缩向量上算，完整 K/V 从头到尾不需要真的算出来，省显存又不把计算加回去。剩一个零件不配合：RoPE 要按位置旋转，正好夹在 Q 和 K 中间，于是把位置单独拎出 64 个数由 128 个头共用，512+64=576 个数/层/token，约是标准多头 32768 的 1/57，比 8 组 GQA 的 2048 还小；乘 61 层、两字节，标准多头近 4MB 而 MLA 约 69KB，DeepSeek-V2 论文里 MLA 效果还略优于标准多头。

为什么推荐：这是推理成本的底层账本：KV 缓存直接决定显存占用、并发上限和长上下文的单价，理解 MLA 才能自己估算部署规格，也能反过来读懂 GQA/MQA 的取舍。属模型结构与推理侧知识，与板卡、驱动、端侧部署无关。

适用场景：适合在学完注意力机制和 KV cache 基础之后看，作为推理成本估算与模型结构对照的中间一环；看完可用同一套算法手算 GQA、MQA、MLA 三者的每 token 缓存量对齐。

一天一个Linux命令，零基础入门Linux命令合集

bilibili · 高鲲教育 · 嵌入式 Linux

视频链接：https://www.bilibili.com/video/BV1nyst6VEaJ

推荐等级：推荐

核心问题：零基础怎么把 cat 真正用成排查工具，而不是只会“cat 一个文件看内容”。

关键方法 / 结论：以查 /etc/os-release 判断发行版为例说明 cat 的定位：Linux 一切皆文件，想知道软件配置就看配置文件、想知道运行过程就看日志文件，cat 就是最直接的入口（示例里三台看着一样的机器分别读出麒麟 V10、CentOS 7、Ubuntu 24.04.3 LTS）。参数上 -n 给每行加行号便于定位，-b 只显示非空行，配置里空行多时很省眼。合并文件可以直接 cat a.txt b.txt c.txt > out.txt 把内容串成一个文件，此时要分清 > 覆盖与 >> 追加，否则一条命令就把原文件冲掉。片尾两个提醒更值得记：不要用 cat 打开大文件，会把终端和系统拖到卡死，大文件应换分页或截取类命令；用 > 写文件前先确认目标文件能不能被覆盖。

为什么推荐：属嵌入式 Linux 基础命令层的最小可用工具集：上板后第一步往往是读配置、读日志，cat 配合行号参数和重定向就够完成大半初查，也能顺带建立“标准输入输出可组合”的 shell 直觉。

适用场景：适合 Linux 入门第一周和刚上板调试的阶段；建议在真机 /etc 与 /var/log 下把 -n、-b、多文件合并三组各练一遍，并把 > 与 >> 的差别亲手验证一次。
