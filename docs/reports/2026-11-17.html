重要内容

架上一个 ESP32 摄像头，识别猫咪去了哪个猫砂盆

bilibili · 电磁波Studio · 嵌入式 Linux

视频链接：https://www.bilibili.com/video/BV1gtsr6aEgR

推荐等级：推荐

核心问题：想让设备“看懂”画面里的行为（哪只猫用了哪个盆、待了多久），端侧摄像头这一层该承担多少计算，视觉模型究竟放在哪一头。

关键方法 / 结论：架构是分层而不是“把大模型塞进 MCU”。ESP32 摄像头只负责采集与推流，实测 15~16 fps，日常观看足够流畅；旁边一块 ESP32 小屏当取景框方便调角度，桌面屏显示实时画面与统计结果。真正的“理解行为”交给 MiniCPM-V 4.7 这类 35B 总参 / 3B 激活的视觉理解模型，由它判断画面里有没有猫、在哪只盆前逗留多久，再按天汇总成“哪只猫、去了几次、哪个盆”的表。关键判断点就在模型体量上——35B 级的 MoE 视觉模型不可能跑在 ESP32 上，所以这条链路本质是“端侧采集 + 侧端/云侧推理”的端云协同，不是纯端侧推理；作者把代码开源在 letterbox vision 仓库。

为什么推荐：这是当天唯一一条走完整闭环的真实项目：采集 → 传输 → 视觉理解 → 结构化统计，正好回答你方向里最容易含糊的问题——大模型和单片机各自该干什么。把链路拆开就能得到一个可复用模板：MCU 管时序与采集，语义理解放在有算力的那一端，中间只传必要数据。

适用场景：做摄像头类、行为识别类端侧项目（毕设、智能家居、宠物或老人看护）时当架构参考；也可以拿它来校自己的算力预算：先估模型要多少内存与算力，再决定推理放板上还是放网关或服务器。

还在纠结选 ESP32 还是 STM32？

bilibili · 软妹不能玩单片机吗 · 嵌入式 Linux

视频链接：https://www.bilibili.com/video/BV1cbsg6hEpg

推荐等级：推荐

核心问题：入门阶段在 ESP32 和 STM32 之间怎么选，才不会学到一半才发现方向错了，或者先被前期的门槛劝退。

关键方法 / 结论：作者把两者讲成两条互补的路而不是对立的两派，并给出可操作的三条选择标准。ESP32 自带 WiFi 与蓝牙，Arduino、MicroPython、ESP-IDF 三套开发方式都能用，一周内就能做出可演示的东西，代价是运行功耗偏高、实时性只够基础控制，精密电机控制别硬上；STM32 外设丰富（多路定时器、USB OTG 等）、中断响应快、实时性强，是电机控制、机器人、工业现场的主场，也有专门的超低功耗系列，但多数型号不带无线、需外接模块，HAL 库与寄存器这一关是主要劝退点。标准是：想先拿到成就感、项目主线要联网上云、编程底子薄想先用 Python 跑起来 → 选 ESP32；想把底层（时钟树、中断、外设）吃透、目标岗位写的就是车载/工控/电机驱动、毕设偏控制类且时序严格 → 选 STM32。另有一句值得记住：带 PSRAM 与向量指令的 ESP32-S3 已能做摄像头、离线语音、轻量模型部署，是通向 AIoT 最近的一条路。

为什么推荐：你现在正处在“先啃哪块板子”的决策点上，这条把两者的能力边界和劝退点都摆到明面，能避开“学两周灯都没点亮就放弃”的常见坑。对你 AI大模型+嵌入式的方向更有用的是后半段——它把 ESP32-S3 标成端侧轻量模型的低成本入口，STM32 线通向电机与工控，这正好是选端侧项目载体时要做的取舍。

适用场景：现在就能看，属于买板子、定学习顺序之前的选型参考。适合用来给自己排一个“先用 ESP32 出成果、再回头补 STM32 底层”的顺序；毕设选题偏控制类时，也用它判断该不该直接上 STM32。
